开发者指南 / HTTP 429

AI API 返回 429，先查哪一步？

429 通常意味着请求过于频繁，但具体原因应以实际响应正文为准。更换接口地址并不能保证解决限流，也不要在失败后无限重试。

先记录响应，再定位请求

记录状态码、错误正文、请求时间及请求 ID（如果响应提供）。请勿把完整 API Key 发给他人。用最小请求复现问题，确认调用的是预期模型和接口。

检查密钥、额度和模型

  1. 登录后检查密钥管理中的有效期、权限和配额，以及账户可用余额。
  2. 在模型广场确认目标模型是否可用，并用 /v1/models 查询当前密钥能看到的模型。
  3. 若同时启动了多个编辑器插件或自动化任务，减少并发，再逐步恢复。

以有限次数重试

仅在可重试错误上使用指数退避；若响应提供 Retry-After，优先遵循其等待时间。持续失败时停止重试并保留脱敏后的错误信息，检查配额或联系站点支持。

接入前可先按照OpenAI 兼容 API 教程用单个请求验证密钥。本文是排查路径，不承诺任何模型始终可用。
